## PART 0 — Verdict

**The project is not fraudulent and its arithmetic is clean (≈60 headline numbers
independently recomputed across the prior audit, zero arithmetic errors). But the
paper draft in submission format (`Paper_Draft/ATLAS_INITIAL_DRAFT.tex`) is built on
numbers that are either superseded (E0 UMF trend, ~+23% optimistic on the anchor) or
in an unresolved reproduction conflict (the E2 routing headline, 60.3 / 36.5 — the
project's own docs say it "reversed to below chance" on 2026-08-28; xray Agent 5's
forensics say that reversal is a misconfigured re-run using pre-rollout-fix charts
and the result actually survives at ≈0.63 / 0.29). Nobody has run the deciding
experiment.** The strongest *unambiguously surviving* result is a negative/mechanistic
one (N3: the CEM planner's candidate ranking, not the world model's prediction
accuracy, is what collapses under a physics shift, with a clean no-shift control). Two structural
facts dominate everything: (a) `num_act_stepped=6` means every planning number in
the project comes from **exactly one open-loop CEM plan per episode**, so the
adaptive/continual loop the paper describes has never run in any experiment that
produced a number; (b) the offline chart-training data is generated by an objective
("make contact with the block", rejection-sampled) that is not the task objective
("push the block to the goal") — a genuine objective substitution on the
`scripted`/`hybrid` collectors, layered on top of the R0-recorded / open-loop /
contact-conditioned mismatches the audit already documents. Individual code
mechanisms (UMF, Chart apply/restore, pairing, `stats.py`, the rollout fix) are
sound. The incoherence is between *what the paper claims* and *what the experiments
structurally can show*.

> ## HIGH severity
>
> ### H1. "S-dyn" is described as appearance/visual-similarity based, but it is implemented as a model-prediction signal
> - **Locations in .tex:** abstract ("an appearance-based dynamics-fingerprint router"), §Experimental Setup l.57 ("routes using an appearance-derived dynamics fingerprint"; "S-dyn tests whether input similarity alone can recover the correct specialist"), §Method l.41 context, §Results 4.1 l.66 ("a world model's own realized prediction error contains information that appearance-based similarity misses"), Table 1 row, §Conclusion l.138 ("substantially better than an appearance-based router").
> - **Inconsistency:** `atlas/router.py::_sdyn_score` (l.171–198) implements S-dyn as *negative cosine similarity between the observed first-step latent delta (z₁−z₀) and the chart-conditioned predicted delta (ẑ₁−z₀)*. It applies each chart, runs the frozen predictor, and compares to the observed transition — it is a prediction-error signal, differing from UMF only in functional form (first-step direction cosine vs. normalized multi-step squared magnitude). It uses no appearance/pixel/visual-similarity features. The router.py module docstring and `ATLAS_proposal_v7.md` §215/§516 call it a "dynamics fingerprint" and frame the finding as "route by dynamics, not appearance." The proposal's actual appearance-based router is **S-obs**, which was deferred to supplementary and appears never to have been run.
> - **`PAPER_DRAFT.md` is correct:** l.128 defines S-dyn as "action-conditioned latent-delta cosine similarity" — no "appearance" claim. `ATLAS_SUMMARY.md` l.382/387 propagates the same error as the .tex ("similarity to what the scene looks like", "appearance-based baseline").
> - **Why it matters:** the paper's headline routing contribution ("predictive fitness beats appearance-based routing") is not what the experiment tests. The honest contrast is: normalized multi-step latent prediction error (UMF) vs. a first-step latent-delta direction cosine (S-dyn) — two formulations of predictive fitness. There is no appearance-based baseline in the results.
> - **Suggested fix:** Replace every "appearance-based / appearance-derived / input similarity" description of S-dyn with its true mechanism (e.g. "a first-step latent-delta direction-matching baseline"). Reframe the 4.1/4.3 claim as "the normalized multi-step formulation of predictive fitness outperforms a single-step direction-cosine formulation." Either add a genuine appearance-similarity baseline (S-obs) or drop all "appearance" comparative language from the abstract, contributions, and conclusion. ### CHECK 2 — THE HYBRID COLLECTOR'S ACTUAL OBJECTIVE

**Question.** Does the `scripted`/`hybrid`/`closed_loop` data-collection code in
`scripts/run_e0.py` optimise "push the T-block toward the goal", or something
easier ("approach/contact the block") that may have been substituted in after a
prior session saw near-zero contact? If the latter, name it as an objective
substitution, separately from OPUS #11's "two variables confounded" framing.

**What the code says (`scripts/run_e0.py::load_regime_trajectories`).**

- **`scripted` and `hybrid` share the same action generator** (the `else` branch,
  lines 312–349):
  ```python
  block_xy = state[2:4]
  target = block_xy + rs.uniform(-40.0, 40.0, size=(2,))   # once per trajectory
  agent_xy = obs["proprio"][:2]
  for _ in range(traj_len):
      direction = (target - agent_xy) / env.action_scale
      noise = rs.normal(0.0, 0.15, size=(2,))
      ACTION_GAIN = 0.25
      act = np.clip((direction + noise) * ACTION_GAIN, -1.0, 1.0)
      obs, reward, done, info = env.step(act)
      agent_xy = obs["proprio"][:2]
      total_contacts += info["n_contacts"]
  ```
  **There is no goal anywhere in this branch.** The "target" is a random point
  within 40 px of the block's *initial* position, fixed for the trajectory. The
  agent aims at that point. The result is: the agent walks into the block and
  bumps it in a roughly random direction. The only difference `hybrid` vs
  `scripted` is that `hybrid` resets to a *real dataset init state* first
  (line 235–245) instead of a fresh random reset.
- **Acceptance criterion** (line 351): `if total_contacts > 0 or attempt == max_tries - 1: break`.
  A trajectory is **rejection-sampled on having made contact**, up to `max_tries=8`.
  No criterion involves the block moving toward anything.
- **The docstring itself records the history** (lines 91–97): the *original* scheme
  was per-step IID random actions, which "produce agent-block contact in only
  ~13–17% of rollouts"; it was redesigned to the aimed-walk + rejection scheme.
  `ACTION_GAIN=0.25` was then "tuned empirically" (lines 328–341) to match the
  checkpoint's action-magnitude statistics, and the comment notes the aimed walk
  alone reaches "~43% single-attempt contact", with "~99% expected overall" from
  the `max_tries=8` retry loop.
- **`closed_loop`** (lines 278–311, and `--collect-*` flags): *does* use a real
  goal — `sample_dataset_init_goal(...)` and a real `GC_Agent`/CEM planner
  replanning each chunk. But the `--collect-num-act-stepped` flag that is supposed
  to control its closed-loop-ness is documented (lines 553–573, 645–662) as a
  **no-op**: "in the current collector, this flag does NOT change replan cadence or
  the resulting trajectory at all". And `closed_loop` was collected at 100×10 CEM
  vs the 300×30 eval budget (a 9× gap; `--collect-num-samples` default was 300 only
  after FIX_SPEC E-C).

**My conclusion (formed before opening `SUBMISSION_PLAN.md` / `PROPOSAL_CODE_ALIGNMENT.md`).**

**Yes — this is an objective substitution, and it is a more fundamental problem
than "two variables confounded."** The scientifically relevant objective for E0's
chart training is: *generate transitions that stress the regime difference in a way
a goal-directed planner will actually encounter*. What the `scripted`/`hybrid`
collectors optimise instead is: *make the agent touch the block*, with the block's
resulting motion being direction-random and task-irrelevant. The acceptance test is
literally `total_contacts > 0`. This is the classic proxy-objective substitution
pattern: an honest objective (goal-directed pushing) gave a weak signal (13–17%
contact under naive random actions), and a prior session replaced it with an easier
proxy (contact rate) that is cheap to satisfy but measures something adjacent to
the thing that matters.

Consequences:
- A chart trained on `scripted`/`hybrid` data is fit to predict the latent dynamics
  of *random-direction block bumps under the shifted physics*, not *goal-progress
  dynamics*. This plausibly explains the `lora4` failure mode recorded in
  `CLAUDE.md` §0.1 ("more contact than any other chart, but wrong-direction
  pushes").
- It is a *distinct* issue from OPUS #11. OPUS #11 says `hybrid` changed two
  variables at once (open→closed loop AND recorded-actions→scripted-actions), so
  its worse performance is ambiguous. That is true but understates it: **even
  holding OPUS #11 aside, the scripted action objective was never goal-directed**,
  so `hybrid` (and `scripted`) never tested "does a chart trained on
  regime-appropriate goal-directed data help" at all. The `hybrid` conclusion in
  `E0_RECOVERY_PLAN.md` §0.6 ("dataset replay wins") is comparing goal-directed
  expert replay against a contact-seeking random walk — not a controlled contrast.

**What partially rescues the headline.** The *default* collector is
`--data-source dataset` (line 519), which replays **real expert demonstration
action sequences** (goal-directed by construction — they are expert task
completions). The N=100 planning result (44 vs 43) and the UMF sweep use `dataset`.
So the *headline* E0 numbers are not objective-substituted. The concern is scoped
to: (i) the `scripted` and `hybrid` arms and any conclusion drawn from them
(including the dissociation-figure inputs in `SUBMISSION_PLAN.md` A-iv, where
`ln_act/hybrid` appears as a row); (ii) `A-viii` in `SUBMISSION_PLAN.md` — the
contact-conditioning of even the `dataset` collector (every trajectory is
rejection-sampled on `total_contacts > 0` in *all* sources, lines 351–352), which
means even the expert-replay training distribution is conditioned on contact while
CEM's candidate distribution (~80% contact) is not.

**Comparison with prior write-ups.** Partially independent. `SUBMISSION_PLAN.md`
A-viii and Part C-1 capture the *contact-conditioning* half (rejection sampling
conditions the training distribution on contact). `OPUS_REMAINING_TASKS.md` #11
captures the *two-variables* half. **Neither states plainly that the
`scripted`/`hybrid` target has no goal in it at all** — that the generating
objective is "walk to a random near-block point", not "push toward the goal". That
is my addition, and it is the sharper framing: it is not that `hybrid` is a
confounded test of the open/closed-loop axis; it is that `hybrid` never
instantiated a goal-directed objective, so it is not a test of chart utility under
*any* interpretation.

|---|---|---|---|
| claim-affecting | `scripts/run_e0.py:312–352` | `scripted`/`hybrid` target = `block_xy + U(−40,40)`, no goal; accept iff `total_contacts>0` | Retract any `hybrid`/`scripted` chart-utility conclusion. Do not put `ln_act/hybrid` in the dissociation figure without stating its training objective was contact, not goal-progress. |

### 3.4 What the paper can honestly claim at 6–7 pages

- **Corroborate:** N1/N2/N4 as an explicitly-scoped negative result — a ~10.7k-param
